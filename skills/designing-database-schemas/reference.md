# Schema defaults, one line each

PostgreSQL unless marked. Each row links the post with the measurements behind it.

| Decision | Default | Choose otherwise when | Why |
|---|---|---|---|
| Primary key | `bigint GENERATED ALWAYS AS IDENTITY` | ids are made outside the database or rows move between systems: UUIDv7. Never UUIDv4 as the key; put it in a separate public-id column | key width repeats in every FK and index; random values scatter inserts ([uuid vs bigint](https://schemity.com/blog/postgres-uuid-vs-bigint-primary-key/), [serial vs identity](https://schemity.com/blog/postgres-serial-vs-identity/)) |
| FK column type | exactly the referenced key's type (plain `bigint`, never `serial`) | - | MySQL also needs the same sign; mismatches fail with error 3780 ([MySQL unsigned vs signed](https://schemity.com/blog/mysql-unsigned-vs-signed-primary-key/)) |
| Status or type column | `text` + named `CHECK (col IN (...))` | values carry data or non-developers edit them: lookup table + FK; a closed set that never changes: native enum | enum values cannot be dropped, and changes lock every table using the type ([enum vs check vs lookup](https://schemity.com/blog/postgres-enum-vs-check-constraint-vs-lookup-table/)) |
| Instants (`created_at`, event times) | `timestamptz` | wall-clock values (opening hours, birthdays): `timestamp` | `timestamp` is silently wrong across zones and DST, at the same 8 bytes ([timestamp vs timestamptz](https://schemity.com/blog/postgres-timestamp-vs-timestamptz/)) |
| Strings | `text` | the limit is a real rule (country code, an external system's limit): `varchar(n)` or a CHECK | both store the same; a guessed limit fails later ([varchar vs text](https://schemity.com/blog/postgres-varchar-vs-text/)) |
| Money | `numeric(p,s)` | `bigint` minor units with currency (and its exponent) stored | floats sum inexactly; `money` is locale-bound and currency-less ([numeric vs double vs money](https://schemity.com/blog/postgres-numeric-vs-double-precision-vs-money/)) |
| Unique rule | a named unique constraint | conditional (not soft-deleted): partial unique index; on an expression: expression index | only constraints are FK targets and read as rules by tools ([constraint vs index](https://schemity.com/blog/postgres-unique-constraint-vs-unique-index/)) |
| Nullable column in a unique key | a partial unique index `WHERE col IS NOT NULL` when only some rows carry the value (an id imported from another system) | must hold for every row: `NOT NULL`, or `NULLS NOT DISTINCT` (PostgreSQL 15+); SQL Server allows one NULL | rows with a NULL key column skip the check on PostgreSQL, MySQL, SQLite, and the partial index says so on purpose ([unique and nullable](https://schemity.com/blog/unique-constraints-and-nullable-columns/)) |
| Foreign keys | declared, indexed | the engine does not enforce them, an online-schema-change tool forbids them, or rows live on other shards: document the relation instead | only the database sees every write path ([should you use FKs](https://schemity.com/blog/should-you-use-foreign-key-constraints/)) |
| ON DELETE | per FK: CASCADE / SET NULL / RESTRICT by what the child means alone (SQL Server: NO ACTION, it has no RESTRICT) | never CASCADE across modules; SQL Server refuses two cascade paths into one table (Msg 1785) | unset is NO ACTION, and cascades are unseen in reviews ([set null vs cascade](https://schemity.com/blog/postgres-on-delete-set-null-vs-cascade/), [cascade is invisible](https://schemity.com/blog/on-delete-cascade-is-invisible-in-your-erd/), [modular monolith](https://schemity.com/blog/foreign-keys-between-modules-modular-monolith/)) |
| Deferrable FKs | `NOT DEFERRABLE` | one job writes out of order: `DEFERRABLE INITIALLY IMMEDIATE` + `SET CONSTRAINTS ... DEFERRED` | immediate checks fail on the statement at fault ([deferrable FKs](https://schemity.com/blog/postgres-deferrable-foreign-keys/)) |
| FK cycles | at least one side nullable, where absence is real; or move one reference to its own table | - | an all-NOT-NULL cycle accepts no first row; MySQL and SQL Server cannot defer ([circular FKs](https://schemity.com/blog/circular-foreign-keys-first-row-cannot-be-inserted/)) |
| Many-to-many | junction table | elements are values the row owns (free-form tags): array column | arrays carry no FK or ON DELETE ([array vs junction](https://schemity.com/blog/postgres-array-column-vs-junction-table/), [junction tables](https://schemity.com/blog/many-to-many-shouldnt-mean-hand-building-the-junction-table/)) |
| One child, many parent types | exclusive arc: one nullable FK per parent + CHECK exactly one is set | many parents: supertype table; open-ended: `type` + `id` with a CHECK on `type`, documented | no FK can point at `commentable_id` ([polymorphic associations](https://schemity.com/blog/postgres-polymorphic-associations/)) |
| Derived value | generated column (same row, immutable functions) | `now()`, other rows or tables: trigger | triggers can be bypassed and break late on renames ([generated column vs trigger](https://schemity.com/blog/postgres-generated-column-vs-trigger/)) |
| `updated_at` | set by the ORM when one app owns every write | anything syncs or invalidates on it: database-side (MySQL `ON UPDATE`, else a trigger) | only the database sees every write ([updated_at](https://schemity.com/blog/auto-update-updated-at-column-mysql-postgres-orm/)) |
| Multi-tenant users and roles | `users` (person) + `members` (user in tenant); `roles` with `tenant_id` and `unique (tenant_id, name)`; `permissions` system-wide | - | password policy and settings differ per tenant ([RBAC data model](https://schemity.com/blog/design-data-model-for-multi-tenant-rbac/), [roles and permissions](https://schemity.com/blog/design-roles-and-permissions-for-multi-tenant-rbac/)) |
| Embeddings (pgvector) | a `chunks` table with the vector; `chunk_embeddings (chunk_id, model)` if you will re-embed | one vector per entity on a row nothing else updates: a column | updates to the row grow the HNSW index ([embedding column vs table](https://schemity.com/blog/pgvector-embedding-column-vs-separate-table/)) |
| Constraint names | `<table>_<columns>_<suffix>` | - | under 63 bytes; index-backed names are unique per schema ([naming convention](https://schemity.com/blog/postgres-constraint-naming-convention/)) |
| Widening `int` to `bigint` on a big table | new column, backfill, unique index `CONCURRENTLY`, swap with `ADD PRIMARY KEY USING INDEX` | a maintenance window allows the in-place `ALTER TYPE` | the in-place rewrite locks both ends of every FK ([int to bigint](https://schemity.com/blog/postgres-change-int-primary-key-to-bigint/)) |
| NOT NULL column on a big table | see SKILL.md rule 5 | - | volatile defaults rewrite the table ([add NOT NULL column](https://schemity.com/blog/postgres-add-not-null-column-large-table/)) |
